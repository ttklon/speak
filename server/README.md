# Приёмник журналов ZSpeakly (необязательно)

> **Этому приложению приёмник не нужен.** По умолчанию журнал пишется на компьютере,
> а отчёт сохраняется одной кнопкой «Диагностика → Сохранить отчёт в файл».
> Ни аккаунтов, ни регистрации. Папка нужна только тем, кто сам хочет собирать
> журналы с нескольких машин.


Один Cloudflare Worker. Приложение отправляет сюда служебные события
(`POST /v1/events`), воркер вычищает персональные данные и складывает их
в собственное хранилище — **Durable Object с SQLite внутри воркера**.

Для развёртывания нужен аккаунт Cloudflare и настроенный Wrangler; отдельные
репозиторий и база данных не обязательны.

> **Не разворачивайте этот приёмник публично без дополнительной защиты.** Без
> `LOGS_SECRET` читать и отправлять журналы может любой, кто знает адрес. При
> заданном `LOGS_SECRET` сервер требует его и для POST, но текущий desktop-клиент
> этот заголовок не отправляет: отправка с него не заработает. Секрет в URL
> `/admin?key=...` также может попасть в историю браузера и журналы прокси.
> Разделение ключей чтения и записи и совместимый защищённый клиент пока не
> реализованы; безопаснее использовать локальный отчёт.

## Развернуть

```bash
cd server
npx wrangler deploy
```

Всё. Адрес воркера (`https://zspeakly-logs.<ваш-поддомен>.workers.dev`) должен
совпадать с адресом в `electron/logger.cjs` или задаваться переменной
окружения `ZSPEAKLY_LOG_ENDPOINT`.

Секрет `LOGS_SECRET` ограничивает **и чтение, и POST**. Он не поддерживается
текущим desktop-клиентом и не решает всех проблем публичного развёртывания.
Для проверки защищённого сервера вручную можно передавать ключ в заголовке
`x-zs-secret` (не вставляйте реальный ключ в документацию или исходники).

## Читать журналы

| Адрес | Что даёт |
| --- | --- |
| `/admin?key=<LOGS_SECRET>` | страница: время, уровень, область, сообщение, данные, стек, версия |
| `/v1/events?limit=100&key=...` | то же в JSON |
| `/health` | состояние приёмника и способ хранения |

Страница `/admin` — обычный HTML, открывается в любом браузере, ошибки
подсвечены красным. Хранится 30 дней и не больше 20 000 событий: старое
удаляется само, воркер не растёт бесконечно.

## Что приходит

Только то, что нужно для починки:

| Поле | Пример |
| --- | --- |
| `level` | `error`, `warn`, `info` |
| `scope` | `stt`, `dictation`, `renderer`, `main` |
| `message` | `Распознавание не удалось` |
| `data` | `{ bytes: 96_000, model: "small", ms: 4200 }` |
| `stack` | первые строки стека |
| `app` | `{ version, platform, arch, engine }` |
| `installId` | случайный uuid, не связан с человеком |

Клиент и сервер пытаются исключать известные поля с текстом диктовки, буфером,
аудио и промптами и маскировать некоторые почтовые адреса, домашние пути и
токены. Это эвристики, а не гарантия удаления всех личных данных: произвольные
сообщения, другие имена полей и форматы путей могут содержать чувствительную
информацию. Проверяйте отчёт перед передачей.

## Копия в GitHub (необязательно)

Если хочется ещё и файлы в репозитории — задайте `LOGS_REPO` в
`wrangler.toml` и `npx wrangler secret put GITHUB_TOKEN` (fine-grained,
Contents: RW). Без этого шага всё работает на встроенном хранилище.

## Проверить

```bash
curl -s https://zspeakly-logs.workers.dev/health
curl -s -X POST https://zspeakly-logs.workers.dev/v1/events \
  -H 'content-type: application/json' \
  -d '{"installId":"test","app":{"version":"1.4.1"},"events":[{"level":"error","scope":"stt","message":"проверка канала"}]}'
```

Ответ `{"ok":true,"stored":1}` означает, что событие легло в журнал; смотрите
его на `/admin`. Если приёмник недоступен, приложение продолжает работать:
события остаются в `%APPDATA%\ZSpeakly\logs\zspeakly.log`, а «Диагностика →
Скопировать ошибки» собирает их в текст.
