# ZSpeakly — архитектура приложения

Документ описывает, как устроена **реализованная** версия (Electron + React).
Альтернативный .NET-план остался в [06-ARCHITECTURE-NET.md](06-ARCHITECTURE-NET.md) — он не отменён,
но этот репозиторий теперь собирает Electron-приложение.

## Почему Electron, а не WPF

| Критерий | Electron (выбрано) | WPF + Whisper.NET |
|---|---|---|
| Скорость выхода MVP | UI из видео воспроизводится 1:1 на CSS за дни | XAML-стилизация каждого контрола |
| Кроссплатформенность | Windows/macOS/Linux одним кодом | только Windows |
| Web Speech / Media API | встроены (микрофон, WebAudio, VAD-уровень) | нужен NAudio + Silero ONNX |
| Офлайн-STT | whisper.cpp отдельным бинарником | Whisper.NET (проще) |
| Размер дистрибутива | ~85 МБ (NSIS) | ~25 МБ framework-dependent |
| Экосистема для UI | React, lucide, CSS-переменные | ограничена |

Итог: Electron выбран за скорость воспроизведения интерфейса и переиспользование веба,
при этом распознавание остаётся локальным (whisper.cpp) — никакой сети в рантайме.

## Слои

```

  main.cjs      окно, трей, глобальные хоткеи, буфер, IPC, вставка текста

  store.cjs     JSON-хранилище профиля (атомарная запись, flush по таймеру)

src/                          renderer (React 18 + Vite)
  state/
    AppDataProvider      настройки, диктовки, словарь, буфер, пресеты, сессии, заметки, статистика
    DictationProvider    сессия диктовки, уровень, таймер, HUD, глобальный хоткей
    ToastProvider        уведомления
  lib/
    recognition/engine   три движка STT с прозрачным фолбэком
    ai/textops           офлайн-операции: clean / formal / shorten / bullets / terms
    ai/summarizer        резюме встреч: TF по предложениям, решения, задачи
    translate            офлайн-словарь + правила, опционально Ollama

  pages/       Home, Dictionary, Hotkeys, Meetings, Translate, Clipboard
```

## Поток диктовки

1. **Старт.** Глобальный хоткей `Ctrl+Alt+Space` ловится в main (`globalShortcut`) →
   `webContents.send('hotkey', {type:'down'})`. В браузере-превью — `Alt+D` или кнопка «Начать диктовку».
2. **Запись.** `createRecognizer()` выбирает движок:
   - native whisper.cpp (если main нашёл бинарник и модель),
   - Web Speech API,
   - если Web Speech не поднялся за 2 с (`watchdog`) или недоступен — честная ошибка с подсказкой;
     выдуманного «демо-текста» нет.
   Перед стартом записи забирается «горячий микрофон» (`micWarm.take()`): если настройка включена,
   поток уже открыт и последние 0,6 с уходят в запись первыми отсчётами — первое слово не теряется.
   Пауза (`recorder.pause()`): микрофон остаётся открытым, `onaudioprocess` перестаёт копить звук,
   таймер записи не тикает. Продолжение — `resume()`, уже сказанное сохраняется.
3. **Живой текст.** Web Speech отдаёт промежуточные результаты сам. whisper так не умеет, поэтому
   раз в 2,5 с (`streamIntervalMs`) накопленный звук (`pcmRecorder.snapshot()`, окно до 30 с)
   уходит в `stt:transcribe-pcm` с `partial: true`; ответ обновляет черновик и HUD. Запросы идут
   строго по очереди, при остановке цепочка отменяется, а «протухшие» ответы отбрасываются по
   номеру поколения. Перед итоговым проходом незавершённый живой **отменяется** (`stt:cancel` →
   `whisper.cancel()`), иначе два whisper-процесса с моделью в памяти работали одновременно.
   По умолчанию живая расшифровка выключена: с моделью `small` она превращала 30-секундную запись
   в минуту ожидания. Если запись длиннее окна, черновик начинается с многоточия: хвост не
   выдаётся за весь текст. Настройка «Живая расшифровка» выключает всё это целиком.
4. **Финиш.** Пока идёт распознавание, в плашке видно «Транскрипция… N с», номер фрагмента и кнопку
   «Отменить» (`cancelProcessing` → `stt:cancel`). Затем `onEnd` → `finish()`: словарь → постобработка
   → запись в историю → статистика.

   **Быстрый путь.** После остановки фраза распознаётся ОДНИМ проходом движка, если она короче
   15 секунд — пауза в середине фразы больше не делит её на несколько проходов (каждый проход
   без прогретого сервера заново грузил веса модели). Длинная запись режется по паузам, но не
   больше чем на три части. Полировка локальной моделью (если включена) ждёт не дольше бюджета
   `aiPolishBudgetMs` (1,5 с по умолчанию): не успела — вставляется текст после офлайн-правил,
   а ответ модели дописывается в историю, когда придёт.
5. **Вставка.** По умолчанию `native.insertText(text)` кладёт текст в буфер и отправляет `Ctrl+V`
   активному окну, а прежний буфер возвращается через 500 мс, если его не тронули. Опция «Без
   буфера» (`insertMethod: 'sendinput'`) вместо этого шлёт символы в активное окно событиями
   Win32 `SendInput` с `KEYEVENTF_UNICODE`; при обрыве на середине текст не вставляется буфером —
   иначе задвоился бы — а человек видит, сколько символов уже в окне.

   Если курсор стоит в поле самого приложения (поиск, заметка, правка расшифровки), текст
   вставляется **прямо в это поле** (`src/lib/insertLocal.js`): без буфера, без чужих окон и без
   системной вставки. Раньше такой случай уходил в *предыдущее* окно — то есть не туда, где человек
   писал. Пока идёт запись, интерфейс показывает, куда попадёт текст (`text:target` → название
   активного окна или «поле этого приложения»).

   Оба системных пути идут через **резидентный помощник ввода** (`electron/inputHost.cjs`): один процесс
   PowerShell c уже скомпилированным C# держится живым и общается построчно (`PASTE`, `COPY`,
   `TYPE <base64>`, `PING`). Раньше на каждую вставку запускался новый `powershell.exe` с
   `Add-Type` — сотни миллисекунд (на слабом ПК с антивирусом — секунды), причём дважды за
   диктовку. Помощник поднимается при старте приложения и в момент начала записи, то есть пока
   человек говорит; если он не поднялся, main честно откатывается на одноразовый PowerShell.

Защита от двойного финиша: флаг `finishing` в `DictationProvider` и `ended` в web-движке.

## Хранение

| Среда | Где |
|---|---|
| Electron | `%APPDATA%\ZSpeakly\profile.json` (ключи `zs:*`) |
| Браузер (preview) | `localStorage` с теми же ключами |

Ключи: `zs:settings`, `zs:dictations`, `zs:clipboard`, `zs:dictionary`, `zs:hotkeys`,
`zs:presets`, `zs:instructions`, `zs:sessions`, `zs:meetingNotes`, `zs:stats`, `zs:profile`.

Запись в профиль дебаунсится (180 мс), файл пишется через `.tmp` + `renameSync`.
**Чтение синхронное** (`sendSync` → данные уже в памяти main) — это важно: асинхронное чтение
при первом рендере раньше отдавало `null` и история терялась.

## Распознавание речи

```
renderer ──PCM 16 кГц──▶ main ──writeWav──▶ whisper-cli
   -m ggml-base.bin -f rec.wav -l ru -t <ядра> -nt -np -sns -mc 0 -bs 1
   --vad -vm ggml-silero-v6.2.0.bin -vt 0.5 -vsd 500 -vp 100
   -otxt -of rec.wav.out
        ◀──.out.txt / stdout─── main ◀──текст + ms + rms
```

Флаги собирает `cliArgs()` в `electron/whisper.cjs` — отдельной функцией, потому что их проверяет
тест: `-mc 0` не тащит контекст предыдущей диктовки, `-bs 1` — жадное декодирование (быстрее beam
search, текст для диктовки тот же), `--vad` с Silero (`findVadModel`) — тишина не гоняется через
модель, `-ac` (`computeAudioCtx`) — окно энкодера по длине записи: короткая фраза не считает
полные 30 секунд. Замер: 3 секунды речи — 2,5 с → 0,73 с. Если VAD-модели нет, VAD-флаги не передаются вовсе; если сборка whisper.cpp не знает
`--vad` (старый бинарник), проход один раз повторяется без него — человек не остаётся без текста.

Перед запуском main считает громкость записи (`analysePcm`): тишину и записи короче 0,3 с в
whisper не отправляет, а отвечает `code: 'silent' | 'too-short'` — иначе на пустом звуке модель
выдаёт «Спасибо за просмотр». Ответ, целиком совпавший с известной фразой-галлюцинацией
(`isPhantom`), тоже отбрасывается с `code: 'phantom'`.

`whisper-cli.exe` и `whisper-server.exe` **лежат в установщике** (`resources/bin`): CI скачивает
`whisper-bin-x64.zip` из релизов ggml-org/whisper.cpp и складывает exe+DLL в `build/bin`, а
`extraResources` отдаёт их в `resources/bin`. Там же едет VAD-модель Silero (864 КБ): CI качает её
с HuggingFace, а если тот недоступен — собирает из пакета `silero-vad` скриптом
`scripts/make-vad-model.py`. Модель распознавания при первом запуске докачивается сама
(`models:prepare`: движок при отсутствии → модель `base` 142 МБ) с прогрессом в тосте.

Один проход распознавания за раз: `stt:transcribe-pcm` сериализован очередью, итоговый проход
отменяет живой, новый живой не встаёт за итоговым (`code: 'superseded'`). Запись режется по паузам
не больше чем на 4 фрагмента (каждый фрагмент — это отдельная загрузка модели для `whisper-cli`).
Пустой ответ движка отдаётся как `code: 'unheard'` с человеческой подсказкой, а не техническим
stderr.

Поиск бинарника: `resources/bin`, `%APPDATA%\ZSpeakly\bin`, `PATH`.
Модели: `resources/models`, `%APPDATA%\ZSpeakly\models`, `models/` (игнорируется в Git).
Если выбранная модель не скачана, берётся ближайшая доступная
(turbo → q5_0 → small → base → tiny → medium), а не «ничего».

`--prompt` собирается из словаря (`zs:dictionary`) и терминов с экрана (не больше 500 символов).

Настройка «Держать модель в памяти» (`keepModelLoaded`) включает серверный режим: рядом с
`whisper-cli` ищется `whisper-server.exe`, он поднимается на `127.0.0.1` со случайным портом
(`-m`, `--host`, `--port`, `-t`, `-nt`, `-sns`), а распознавание идёт `POST /inference`
(multipart: `file`, `language`, `prompt`, `response_format=json`). Модель остаётся загруженной,
первая диктовка не платит за холодный старт. В самом проходе сервер **не ждём**: если он уже
прогрет — идём в него, если нет — сразу в обычный `whisper-cli`, а сервер поднимается в фоне после
прохода (два whisper-процесса одновременно делят ядра и оба становятся медленнее).
Сервер закрывается при выходе из приложения (`before-quit`).

Живая расшифровка идёт теми же каналами: промежуточный проход — обычный `stt:transcribe-pcm` с
флагом `partial: true`, без словаря и контекста экрана (итоговый проход по всей записи всё равно
точнее). Временные wav пишутся с уникальным именем и удаляются в `finally`; файлы, оставшиеся
после аварийного закрытия, убираются при старте (`tempCleanup.cjs`).

Статус доступен через `native.sttStatus(model)` — интерфейс показывает движок в
Настройки → Функции → «Модель распознавания».

## Офлайн-обработка текста

- `OPS.clean` — слова-паразиты, пунктуация, заглавные;
- `OPS.formal` — замены в деловом тоне (корректная замена по кириллическим границам слов:
  JS `\b` не работает с кириллицей);
- `OPS.shorten` / `bullets` / `searchQuery` / `lowerTerms`;
- `buildSummary` — частотный анализ предложений, выделение решений (`Решили`, `Согласовали`)
  и задач (инфинитивы, `Нужно`, сроки), без дублей между блоками.

Все операции детерминированы и покрыты тестами (45 тестов). Если в настройках включён Ollama
(`http://localhost:11434`), те же операции пробуют локальную модель и молча возвращаются
к правилам при недоступности.

## Безопасность и приватность

- `contextIsolation: true`, `nodeIntegration: false`, IPC-allowlist в preload.
- Нет сетевых запросов в рантайме, кроме опционального `http://localhost:11434`.
- CSP в `index.html` запрещает внешние скрипты и соединения.
- Пароли в буфере можно не сохранять (`hidePasswords`).

## Никакого Python

Приложение полностью на Electron: main-процесс — Node.js (`electron/main.cjs`), рендерер — React.
Ни в сборке, ни в рантайме нет `python.exe`, PyInstaller, `child_process` на python, сокет-моста
или питон-зависимостей. Внешних процессов ровно три, и все опциональны:

| Процесс | Зачем | Если нет |
|---|---|---|
| `whisper-cli.exe` / `whisper-server.exe` (C++ из whisper.cpp) | офлайн-распознавание | лежат в установщике; если их нет (сборка без интернета) — докачиваются, иначе честная ошибка |
| `powershell.exe` (SendKeys) | вставка текста в чужое окно на Windows | текст остаётся в буфере |
| `tasklist.exe` | имя приложения-источника для буфера | источник = «Системный буфер» |

Всё остальное — Node API: `fs`, `path`, `child_process`, `electron` (clipboard, globalShortcut,
desktopCapturer, Tray, session).

```
npm test               # vitest: 254 теста в 34 файлах (движки, пресеты, буфер, пароли, рендер, самопроверка, помощник ввода, вставка в поле, маршруты, срок хранения, очистка данных, диагностика, хранилище, перевод, звук и эффект печати, микрофон, PCM-запись, запись экрана)
```

## Сборка

```
npm run build      # renderer → dist/
npm run dist:win   # NSIS + portable → release/
```

electron-builder упаковывает `dist/`, `electron/`, `icons/` в asar, а `models/` и `bin/`
кладёт в `extraResources` (и распаковывает из asar), чтобы `whisper-cli.exe` можно было запускать; иконка `icons/icon.ico`
генерируется скриптом `scripts/make-icons.mjs` (PNG + ICO без внешних зависимостей).
