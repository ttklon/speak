# Что приложение делает с вашим текстом

Появилось в 1.21.0. Короткий документ про одно правило: **человек должен видеть, что
приложение изменило в его словах, и уметь это выключить одной кнопкой.**

---

## 1. Почему это вообще вопрос

Диктовка — не транскрипция. Между «микрофон услышал» и «текст появился в письме»
стоит несколько шагов, и каждый что-то меняет:

| Шаг | Что делает | Пример |
|---|---|---|
| Словарь | правит написание ваших терминов | «зи спикли» → «ZSpeakly» |
| Голосовые команды | превращает сказанное в знаки и правки | «запятая» → `,`, «с новой строки» → перенос |
| Очистка | убирает паразитов, повторы, ставит знаки | «ну это, как бы, нормально» → «Нормально.» |
| Оговорки | оставляет то, что вы имели в виду | «в четыре… то есть в три» → «в три» |
| Оформление под окно | знаки и заглавная по месту вставки | в чате без точки, в письме с точкой |
| Полировка моделью | переписывает формулировки локальной моделью | «сделай так, чтобы» → «сделайте так, чтобы» |

Пока эти шаги были невидимы, человек не мог отличить ошибку движка от правки
приложения — и не мог вернуть то, что сказал. Два независимых решения:

1. **«Не трогать мой текст»** — один тумблер, который выключает всё, что
   приложение решает за вас.
2. **«Как распозналось»** — в истории видно, что вернул движок и что стало
   после правок; одной кнопкой можно вернуть исходное.

---

## 2. «Не трогать мой текст»

Настройки → Диктовка → «Не трогать мой текст».

Выключает: очистку, правку оговорок, оформление под окно и переписывание
моделью. Тумблер «Умная полировка» при этом гаснет — она входит в этот набор.

**Не выключает** (и это осознанно):

- **словарь** — вы сами его завели, это ваше указание, как писать ваши термины;
- **голосовые команды** — «запятая», «с новой строки» вы произнесли намеренно;
- **быстрые блоки** — «моя подпись» — это ваш макрос, а не догадка приложения.

Правило записано в одном месте — `src/lib/textPolicy.js`. Не в четырёх условиях,
размазанных по конвейеру: иначе следующая правка снова сделала бы поведение
непредсказуемым. У функции есть юнит-тесты, включая «„не трогать“ сильнее
остальных тумблеров».

---

## 3. «Как распозналось»

Раньше история хранила только готовый текст. Теперь у записи может быть поле
`rawText` — то, что вернул движок **до** правок приложения.

- Поле появляется только когда текст действительно отличается (`src/lib/historyRaw.js`).
- Очень длинные расшифровки не дублируются: сырой вариант хранится до 2000
  символов, дальше — нет (история живёт в бюджете профиля, а не на диске).
- В списке «Недавние» такая запись помечена словом **правлено**.
- В окне записи — блок «Как распозналось» и кнопка **«Вернуть как распозналось»**:
  текст заменяется на услышанный, поле `rawText` убирается, в тосте сказано, что
  дальше приложение этот текст не меняло.
- Старые записи без поля читаются как раньше: различий нет — блока нет.

---

## 4. Что осталось за рамками

- **Показ разницы по словам** (подсветка: это слово исправил словарь, это —
  чистка). Требует хранить не только сырой текст, но и источник каждой правки.
- **Отдельный выключатель для словаря** уже есть — тумблер «Применять словарь
  при диктовке» в разделе «Словарь».
- **Восстановление исходного после правки руками** — история хранит последний
  текст; цепочку версий не ведём.

---

## 5. Как проверить

```bash
npm test                       # политика текста и правило «как распозналось»
npm run test:main              # главный процесс: подсказка, движки, скачивание
npm run test:ui                # экраны: тумблер, метка «правлено», возврат текста
```

В E2E есть два отдельных сценария: «настройки: „не трогать мой текст“ выключает
полировку и сохраняется» и «история: видно, как распозналось…».
