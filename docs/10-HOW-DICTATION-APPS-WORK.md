# Как устроены приложения «речь → текст» и что из этого есть в ZSpeakly

Короткий разбор по открытым источникам: как работают Wispr Flow, superwhisper, Svara,
Phonon-2 и что из их архитектуры реально переносится на локальное Windows-приложение.
Документ нужен, чтобы не изобретать заново и не тащить в продукт чужие ошибки.

## 1. Два лагеря: облако и устройство

| | Wispr Flow | superwhisper | Svara | Phonon-2 |
|---|---|---|---|---|
| Где распознаётся | облако (Baseten на AWS) | локально (Whisper, Apple Silicon) | локально (faster-whisper + CTranslate2) | локально (локальный HTTP-сервер движка) |
| Второй этап | облачная LLM (fine-tuned Llama) чистит и форматирует текст | опционально своя LLM | цепочка правил + локальная LLM | фильтры + склейка фраз |
| Нужен интернет | всегда | нет | нет | нет |
| Задержка | ~700 мс p99, из них ~200 мс сеть | секунды на M1/M2 | зависит от GPU/CPU | ~1–2 с |
| VAD | на сервере | — | Silero VAD | Silero VAD |
| Вставка текста | Accessibility API (macOS) | Accessibility | SendInput / буфер / Shift+Insert | Unicode SendInput |

Общий вывод: **качество даёт не «магия», а конвейер**. У всех четыре — одна и та же цепочка:

```
микрофон → VAD/обрезка тишины → ASR (Whisper) → чистка текста → вставка в активное окно
```

Различаются только тем, где стоит ASR и насколько умна чистка.

## 2. Что именно делает Wispr Flow (по их же публикациям)

1. Глобальный хоткей → захват микрофона.
2. Аудио уходит в облако; ASR уложен в бюджет **< 200 мс**.
3. Сырой транскрипт проходит через **fine-tuned Llama** (TensorRT-LLM, < 200 мс на 100 токенов),
   который убирает слова-паразиты, ставит пунктуацию и подстраивает тон.
4. В LLM подмешивается контекст: имя активного приложения, текст рядом с курсором,
   имена переменных в IDE (отключаемо, пароли исключены).
5. Текст вставляется через Accessibility API.
6. Итог — **~700 мс p99** от конца речи до готового текста; метрика считается по p90/p99, не p50.

Что здесь важно: контекст и второй этап (LLM) дают «человеческий» текст, но платой идёт
приватность и зависимость от сети. Полностью офлайн так не получится — поэтому локальные
приложения компенсируют это более простой, но предсказуемой чисткой.

## 3. Что делают локальные приложения

- **superwhisper**: Whisper локально, выбор размера модели под железо, свои «режимы» с
  постобработкой. Ничего не уходит наружу, но и контекста экрана нет.
- **Svara**: faster-whisper на GPU, Silero VAD, «rolling re-transcription» с подтверждением
  слов (LocalAgreement) для живой расшифровки, **прогрев модели при запуске** (первое слово
  не ждёт компиляции ядер), цепочка чистки: паразиты → отмены → списки → LLM → типографика →
  правила под приложение → словарь. Вставка: SendInput, буфер, Shift+Insert — по типу цели.
- **Phonon-2**: «горячий» микрофон (постоянно открыт, чтобы не было задержки на старте),
  Silero VAD по кадрам 32 мс, предролл перед речью (чтобы не срезать первое слово), отсев
  шума по энергии и уверенности VAD, склейка фраз с повторной подачей предыдущей фразы как
  контекста, отложенная пунктуация на стыке, словарь замен, вставка Unicode SendInput
  (буфер не трогается, кроме очень длинного текста).
- **VoicePad / Whisper-диктовка**: VAD, чёрный список фраз-галлюцинаций
  («Спасибо за просмотр», «Продолжение следует»), вставка через SendInput на Windows.

Общее для всех: **тишину не отправляют в модель**, края записи подрезают, галлюцинации
фильтруют, модель держат тёплой, а текст вставляют так, чтобы не сломать чужое окно.

## 4. Модели whisper.cpp: что выбирать для диктовки

Размеры и скорость — из официального `ggml-org/whisper.cpp` (папка `models`) и замеров
сообщества на Apple Silicon/обычном CPU:

| Модель | Диск | RAM | Скорость | Кому |
|---|---|---|---|---|
| tiny | 75 МБ | ~300 МБ | ~30× realtime | проверить, что всё работает |
| base | 142 МБ | ~400 МБ | ~20× | слабый ноутбук |
| small | 466 МБ | ~700 МБ | ~12× | компромисс |
| medium | 1.5 ГБ | ~2 ГБ | ~6× | максимум качества без turbo |
| large-v3 | 2.9 ГБ | ~3.3 ГБ | ~3× | максимум качества, дорого |
| **large-v3-turbo** | **1.5 ГБ** | **~2 ГБ** | **~10×** | **лучший выбор для диктовки** |
| large-v3-turbo-q5_0 | 547 МБ | ~900 МБ | ~10× | то же, но втрое меньше памяти |

large-v3-turbo — тот же large-v3, но с 4 слоями декодера вместо 32: потеря меньше 1 % WER,
скорость втрое выше. Именно поэтому в ZSpeakly он помечен «рекомендуем для диктовки».

Ключи `whisper-cli`, которые реально влияют на качество диктовки:

- `-t N` — все ядра (по умолчанию 4);
- `-nt` / `--no-timestamps` — без таймкодов;
- `-np` — без служебного вывода;
- `-sns` / `--suppress-nst` — подавление не-речевых токенов: на музыке и тишине модель
  перестаёт выдавать «[MUSIC]» и «Спасибо за просмотр»;
- `--prompt` — начальная подсказка: словарь и термины с экрана. Проверенный приём:
  без подсказки `kubectl` превращается в «cube cuttle», с подсказкой — 28/28 терминов;
- `--vad` + `--vad-model` — Silero VAD (нужен отдельный файл модели).

Альтернатива холодному старту — `whisper-server`: модель загружается один раз, дальше
`POST /inference` с multipart-файлом и `response_format=json`. Так делают локальные
диктовочные приложения, чтобы первая фраза не ждала загрузку модели.

## 5. Что из этого сделано в ZSpeakly

| Приём | Статус | Где |
|---|---|---|
| Каталог моделей с честными размерами и RAM | есть | `src/lib/config.js` → `MODELS` |
| turbo как рекомендуемая модель | есть | там же, пометка «рекомендуем для диктовки» |
| Замена недоступной модели на ближайшую | есть | `electron/whisper.cjs` → `findModel` |
| Все ядра, `-np`, `-sns`, `-nt` | есть | `electron/whisper.cjs` → `transcribe` |
| Подсказка из словаря и терминов с экрана | есть | `stt:transcribe-pcm` → `--prompt` |
| Отсев тишины и слишком коротких записей | есть | `analysePcm` + `code: 'silent' / 'too-short'` |
| Обрезка пауз по краям | есть | `trimSilence` (150 мс до речи, 250 мс после) |
| Фильтр фраз-галлюцинаций | есть | `isPhantom` (русские и английские шаблоны) |
| Прогрев модели / серверный режим | есть, опция | `keepModelLoaded` → `whisper-server`, `POST /inference` |
| Вставка в активное окно | есть | буфер + Ctrl+V, прежнее содержимое буфера возвращается |
| Чистка текста (паразиты, пунктуация, тире, заглавные) | есть | `OPS.clean` |
| Словарь замен терминов | есть | `applyDictionary` |
| Постобработка локальной LLM (Ollama) | есть, опция | `src/lib/ai/textops.js` |
| Контекст активного окна как текст | частично | «диктовка с учётом экрана»: скриншот → локальная vision-модель → термины |
| Silero VAD | нет (заменён отсевом по энергии) | — |
| Живая расшифровка во время речи | нет | HUD показывает уровень, текст — после остановки |
| Предролл «горячего» микрофона | нет | запись начинается по хоткею |
| Вставка через SendInput без буфера | нет | используется буфер + Ctrl+V |

Почему не всё: Silero VAD и предролл требуют постоянно открытого микрофона и отдельной
ONNX-модели (плюс к установщику и к разрешениям), а живая расшифровка с whisper.cpp — это
отдельный поток с пересчётом скользящего окна. Для диктовки «нажал–сказал–отпустил» выигрыш
не оправдывает риска, поэтому сознательно не тащим.
